# 设计方案

## 目标与默认假设

杯杯是一项单实例共享资源。任何时刻只能有一位群友获得预约使用权。群规模较小，群友自助注册即可参与；第一版无需打通 QQ / 微信官方登录，无需自购付费服务器。

## 前端

暖白、鼠尾草绿与陶土色的预约看板。首页优先展示当前时段属于谁、预约时间和剩余时间；下方按天浏览安排，右侧直接完成预约。移动端自然排为单列。个人预约单独查看，减少寻找自己的记录的成本。

登录前不显示其他成员 ID。登录后由服务端返回身份，不允许前端随意填写展示 ID。所有成员字符串使用 `textContent` 写入 DOM，配合 CSP 限制脚本来源。

主界面那只茶杯上的字属于**部署配置**而不是用户数据：部署者在 `wrangler.jsonc` 的 `vars.CUP_MARK` 里填一个字符，留空（默认）则杯子上不显示任何字，与“杯杯 / 姜杯杯”这种通用名与具体名的关系一致——同一个模板，部署者换成自己的那一个字。前端启动时通过公开接口 `GET /api/config` 取这个值。

使用轻量轮询：可见标签页每分钟拉取一次，看板切换、重新联网、切回页面时及时更新。服务端是唯一事实来源；预约提交和释放成功后立即重读。客户端倒计时只用于显示，所有写入重新验证当前服务端时间。同步失败时提示错误；超过 90 秒未同步则标记“状态待确认”。

## 后端与一致性

请求以服务端会话令牌鉴权。注册需要「账号（特征码 1）+ 密码（特征码 2）」：账号全站唯一且不区分大小写，密码以 PBKDF2-SHA256（每用户 16 字节随机盐、50000 轮）哈希保存，明文不落库。迭代次数按 Cloudflare Workers 免费计划 10ms CPU 预算选取；数据库中的记录带迭代次数，后续提高强度时可在登录成功后透明地重新哈希。

登录成功发放 32 字节随机令牌，数据库只保存 SHA-256 哈希，令牌保存在当前标签页 `sessionStorage`，30 天有效；退出登录删除会话，改密码会让其他设备的会话立即失效。每次请求重新检查账号 `enabled`，停用立即生效。同一账号 10 分钟内失败 8 次会被限速拒绝，账号不存在与密码错误返回同样结果，避免枚举账号。

用户可以在账号窗口自定义显示 ID（唯一、1–20 个字符），预约看板展示的是显示 ID，内部仍以不可变的成员 ID 关联预约，因此改名不会改写历史记录。

`members` 记录内部 ID、账号、密码哈希、显示 ID 与启用状态；`sessions` 记录会话令牌哈希与过期时间；`bookings` 记录成员内部 ID、起止时间、原计划结束时间、创建时间与取消时间。UTC 毫秒存储，显示时转换到 UTC+8。

创建预约不采用“应用先查空闲，再独立插入”的逻辑。数据库 `BEFORE INSERT` 触发器在同一写入语句中检查：

```text
已有预约.start < 新预约.end AND 已有预约.end > 新预约.start
```

SQLite 串行处理写入，检查与插入同属一次原子操作，因此并发请求最多一人成功。更新也有防重叠触发器。每人 3 单上限同样在 INSERT 触发器中校验，防止并发绕过。由数据库错误映射为可理解的 409 提示。

取消与提前结束只允许本人操作；校验所有权、尚未结束状态及更新在同一语句执行。到点无需写数据库，不需要常驻进程或 Cron：查询按服务端当前时间判断区间，自然释放资源。

## 部署与费用

前端由 Cloudflare 静态资源分发，`/api/*` 进入 Workers，持久化使用 D1。前后端同源，减少跨域配置与部署步骤。无定时任务、无需 WebSocket、无需 VPS 常驻、无需 Redis。

免费计划限额见 README 中官方链接。小群轻量访问通常可控制在免费额度内，但不是无条件无限服务。轮询避免了常驻实时连接的运维成本；群友同时打开页面人数较多时，应关注 API 请求与 D1 行读取量，再据实际使用调整同步频率。

另一种零云租赁方式是将 Node 后端和 SQLite 放到已有常开电脑/NAS，但这依赖设备开机、家庭网络、HTTPS 与外部访问配置。适合作为本地或已有设备方案，默认推荐托管的 Workers + D1。

## 明确边界

- 预约使用中表示排期上的使用权，系统没有感知杯杯实际状态，也不会自动操作它。
- 账号由群友自己注册，不是 QQ/微信身份认证；谁掌握账号密码就能代表该身份，密码泄露应立即修改或由群主停用。
- 无通知机器人、无需手机号，不会自动向任何群友发送消息。
- 目前只管理一个杯杯；增加多个资源时需引入 resource_id，并将数据库重叠检查按资源分组。
- 不做出勤签到或超时处罚；预约开始后即占用，未到场也不会自动取消。
- 当前查询只针对排期所需时间窗口，但历史记录长期累积时仍应备份和清理。
